# Aves Assessment — Authorized Installer Distribution

Decision: **B — installer download must require authorization.**

## Important repository boundary
`nayihoney-spec/AIPD` is currently a **public repository**. Therefore GitHub itself cannot enforce Aves customer authorization for files committed directly to this repository.

For External Beta, the controlled design is:

1. GitHub contains:
   - source governance;
   - installation documentation;
   - release manifest;
   - link/instructions for the official package.
2. The **official installation ZIP** is generated by the running Aves Assessment service.
3. Download endpoint:
   `GET /api/v1/distribution/install-package`
4. The endpoint requires an authenticated Aves account.
5. Non-Admin users must have active Assessment access.
6. The package contains no production credentials or customer data.

This gates the **official packaged download**, while acknowledging that a public source repository cannot technically prevent someone from reading/building public source code.

If licensing later requires source-level confidentiality, the product code/package must move to a private repository or private package registry. That is a separate governance decision.

## Package contents
- application source required for local runtime;
- Dockerfile;
- docker-compose.yml;
- PostgreSQL and MySQL migrations;
- .env.example;
- Windows `install.ps1`;
- macOS/Linux `install.sh`;
- Installation Guide;
- User Manual;
- Admin Manual.

## Release rule
A package is not considered an authorized release until its version appears in `releases/RELEASE_MANIFEST.md` with QA evidence and rollback target.
